For Janet, first — the four quick ones

Not sure I understand the rewards for contributions — how is that set up?

Two separate thresholds, on purpose. The $15 seed payout triggers on the first approved contribution — an activity, place, tip, or caregiver nomination — the moment one clears review. Founding status is a second, higher bar: a second approved contribution. Both read the same underlying count, so they can't disagree about what "approved" means. Payouts are still sent by hand — no payment rail is wired up, deliberately, since volume is low enough that automating it would be premature.

What does a contributor see when we press Reject?

Nothing at all — not blunt, not friendly, silent. Rejecting flips an internal status column; there's no channel back to a parent yet in any form, because Phase 1 has never needed one. This is the honest state of a real gap: "friendly-ask / hold, never rejected" describes something worth building, but today it's a plain approve/reject with no contributor-facing message either way. Worth deciding if that's fine for the pilot or needs a loop before real numbers arrive.

Paid column looks off — should be $50-$100 vs 50 100?

Confirmed, and the cause is narrow. The data is stored cleanly as an id like 50_100; the admin table's generic formatter turns every underscore into a space and title-cases it — exactly right for per_month → "Per Month," exactly wrong for a price range, where the underscore stood in for a dash. The proper label ("$50–100") already exists in the question definition; the admin display just isn't using it. One clean fix, not a data problem.

Can I try the front end, or still in progress?

Yes, today — there's a live invite you can use right now. One thing worth knowing going in: verification codes currently show on-screen instead of being texted (Twilio isn't provisioned yet), so the flow runs end to end, but the "a real text arrives" moment won't happen until that's live.

4. Digest: manual-only, let reply rate decide. Matches the §3 recommendation exactly.

5. Is Pando still one product? Not something a codebase can answer, but worth noting the current build already reflects the "one front door" instinct — one profile, one identity keyed by phone, one trust graph. Nothing built so far forces the three-company split the strategy doc warns against.
